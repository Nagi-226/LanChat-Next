# LanChat 内的板端面板

## 打开和返回

登录后点击主窗口 **左下角齿轮 → 设置 → 板端连接**，在本体内查看实时连接状态、发送消息和控制板端显示；设置侧栏可切换服务器选项。
点击 **返回聊天 / 返回 LanChat** 回到聊天页。未登录时完整设置不开放；登录页只保留连接所需的服务器地址输入。
重复打开使用同一个面板，保留消息草稿、滚动位置和发送回执；后台桥接继续运行。
面板内容居中，最大宽度为 960 逻辑像素，底部操作按钮与内容区对齐。

## 切换板端的五个页面

操作路径：**LanChat-Next → 左下角设置 → 板端连接 → 连接与屏幕 → 板端页面**。

| 选项 | 板端显示 |
|---|---|
| 总览 | 感知摘要、最新消息、资源状态 |
| 收件箱 | 消息列表，可打开详情 |
| PPM 感知 | 当前感知结果及有效性 |
| VVOS 链路 | PC 连接和收发状态 |
| 设备状态 | 内部堆、PSRAM 和模块接入状态 |

当前板端触摸翻页尚未接入，因此使用 PC 上的这个面板选择页面。
不需要另外打开 RoboMind-Console 的操作窗口；Console 作为后台通信桥运行。
切换页面不会停止 PPM 或消息接收。PC 断开后板端仍保持当前页面，但不能从 PC 下发新的切换操作。

“最新消息详情”“上一条”“下一条”“正文向上 / 向下”“本地标为已读”操作板端收件箱；
本地已读不等于 LanChat 人类阅读回执。

进入板端设置需要先登录 LanChat；状态读取和切换页面还需桥接及板端在线。

## 四项只读查询（2026-11-22）

登录后向专用板端账号发送 **感知 / 链路 / 设备 / 帮助**；在已配置的群中使用 **/感知 /链路 /设备 /帮助**。支持有限的完整同义词，如“感知状态”“网络”“设备状态”。普通群聊天中的单个关键词不会触发。

回复显示在原聊天会话中，含原查询消息 ID。原文字仍有独立的板端显示回执；显示回执不代表查询已完成。感知按未计算 / 无效 / 有效逐项解释，标记采样年龄；过期、离线、旧固件、超时、繁忙和过频均明确反馈。帮助不依赖板端，链路回复同时包含 Console 和 S3 的状态。

关键词走只读确定性接口；另有 PC 模型文字自由问答与追问，见 [AI 使用说明](ai-status-chat.md)。协议与实板验收：[S3 查询协议](https://github.com/Nagi-226/RoboMind-S3/blob/master/docs/status-query-protocol.md)。本机 Tailscale 接入及异地待验：[Tailscale 使用说明](tailscale-setup.md)。

## USB 运行日志（2026-11-23）

打开 **板端连接 → 运行日志**，选择板端 USB 串口并点击 **开始采集**。本机 ESP32-S3 USB Serial/JTAG 枚举为 COM3；更换电脑时按设备管理器选择实际端口。日志由后台 Console 读取 ESP_LOG 和 printf，不修改 S3 固件。

- 级别、模块和关键词筛选；hex 报文默认隐藏，未识别行保留为 RAW。
- 日志页采用深色圆角卡片，标题、筛选和操作分层；时间与级别使用等宽字体，模块使用蓝灰色，警告 / 错误以黄 / 红整行色带和左侧细线标记。页面显示 `HH:mm:ss`，复制和导出保留完整日期、端口与正文。
- 标题栏的 **跟随最新** 默认开启，新输出自动滚到底部，并确保末行在外层页面中可见。向上滚动日志时暂停跟随，滚回底部或重新勾选可恢复；**恢复显示** 会直接跟上最新输出。关闭跟随只影响阅读位置，不停止采集。
- 暂停显示时继续采集，显示待处理条数；清空视图只隐藏当前行，聊天查询缓存仍保留。
- 复制与 UTF-8 导出均使用已脱敏数据，包含主机接收时间和来源端口。时间是主机接收时间。
- 停采、端口占用、未接入和历史缓存分别提示。串口不可用时每 2 秒重试；停止采集立即关闭端口。烧录和其他串口监视器需要独占端口，请先停采。
- 缓存上限 2,000 行 / 4 MiB，单行 2 KiB；历史 5 MiB × 4，最多 20 MiB。显示淘汰、截断、历史缺失与写盘错误计数；驱动层或 USB 断开造成的缺失不保证可精确计数。

日志页右侧可发送真实聊天查询。四种命令在私聊和已配置群中都要求完整匹配：

| 命令 | 回复范围 |
|---|---|
| `/日志` | 最近 20 条已采集日志，默认排除 hex |
| `/日志 错误` | 最近 20 条 ERROR；无记录不等于设备正常 |
| `/日志 链路` | Wi-Fi 与 terminal_tcp |
| `/日志 帮助` | 使用说明，不要求串口在线 |

回复包含原服务端消息 ID、来源、状态、最近时间和数量，总量最多 6 KiB，过长明确截断。日志页筛选与清空操作不改变查询范围。查询不控制采集，也不触发日志自动连续群发；同账号查询间隔至少 750 ms。

本体实时日志页供 USB 相连的主机使用，其他 PC 通过专用板端账号或配置群查询片段。仅 Wi-Fi 日志上行和远程连续订阅为后续阶段。默认不开启 USB 采集；开启偏好在本机保存。

数据位于当前用户的 LanChat 应用数据目录 `board-bridge/logs/`，正文使用独立快照与滚动文件，`status.json` 只含状态和计数。密码、令牌、SSID 和日志中的聊天字段统一脱敏；日志不包含 Console 的账号日志，不进入安装包，不传到 S3。采集前或断开期间的输出无法补取。

## 此前界面验证（2026-11-21）

- Qt 10/10 测试通过，包含主窗口嵌入、无额外顶层窗口、单实例、草稿和滚动位置保留、登录 / 聊天返回路径，以及打开板端页时继续收消息。
- 私聊和群聊统一由服务端 echo 更新消息列表，修复发送后重复出现气泡；连续发送相同正文仍保留两条消息。
- 正式部署 exe 与构建产物 SHA256 一致，两处桌面快捷方式已更新。
- 部署后后台状态确认 `board_connected=true`、`terminal_ready=true`、`decode_failures=0`。
- 本轮只更新本机 Qt 界面，没有重新烧录板端。
