## 2. 明天的实施顺序

### 第一步：完成四项只读查询

沿用当前入口和协议职责：

```text
LanChat 私聊 / 配置群
    → Console 识别查询、保存发起者与会话
    → 读取真实状态；需要时经 VVOS 请求 S3 快照
    → S3 返回结构化状态
    → Console 汇总并格式化
    → LanChat 回复原会话
```

| 查询 | 数据来源与结果 |
|---|---|
| 感知 | PPM 快照：疲劳、眼睛、嘴部、离开时长、退化标志、采样时间及逐项有效性 |
| 链路 | S3 Wi-Fi 与 VVOS 收发状态，加上 Console 的板端连接、LanChat 登录、最近通信时间 |
| 设备 | S3 运行时间、内部堆、最大连续块、PSRAM、模块接入情况 |
| 帮助 | 四项查询的输入方式与能力范围 |

实现约束：

- 私聊专用设备账号可输入 `感知` / `链路` / `设备` / `帮助`；配置群采用明确的 `/感知` 等命令或可验证的设备点名。初版不能靠正文中的任意子串触发。
- 回复关联原 LanChat 消息 ID，并回到发起查询的会话；请求 ID、超时和判重沿用有界处理方式，避免重连/重试产生重复回复和机器人自回复循环。
- 感知逐项保留 **未计算 / 无效 / 有效**，不能将缺失、无目标或无效结果写成“正常”。带采样时间、数据年龄，明确区分当前快照、历史缓存和离线。
- Console 负责综合链路回答。S3 断开后，在线的 Console 仍可返回“板端离线”；需要板端数据的查询返回不可用或明确标记的缓存。
- 状态读取不能阻塞 LVGL、摄像头或现有 TCP pump。S3 继续使用 VVOS 信封，LanChat JSON、账号和会话路由留在 Console。
- 内存、运行时间等信息目前没有完整上行到 Console，实施时需要补充有界的状态请求/响应，而不能从现有连接状态文件推测。
- 查询回复在 PC 聊天框完整展示；板端如需展示摘要，遵守现有 384 字节 UTF-8 上限并核查字库覆盖。附件不进入查询或板端链路。

分工与验收：

- **LanChat-Next**：保持单次消息回显；如有需要增加设备查询帮助入口和会话展示，不再打开额外窗口。
- **RoboMind-Console**：查询路由、同义词表、状态汇总、按原私聊/群回复、限流、超时与判重。
- **RoboMind-S3**：结构化状态快照和 VVOS 请求/响应，保留现有显示、回执及感知数据流。
- 正向检查四项查询、中文、私聊和配置群；负向检查普通聊天不触发、附件不触发、机器人回复不循环、断线/无数据/无效数据有明确回答、重复请求只回一次。
- 涉及固件后执行协议测试、完整构建、烧录同一产物及真板查询往返验证；未完成实机验证不标记完成。

### 第二步：配置并验收 Tailscale 异地连接

- 选定常开主机与一台异地测试 PC，安装官方客户端，加入同一受控 tailnet。涉及第三方账号、计划选择和设备授权时由用户完成身份操作。
- 在 LanChat 填主机 Tailscale 地址或可解析的 MagicDNS 名称及 TCP `12346`。组网授权与 LanChat 注册/群 ID 是独立的访问层。
- 按实际需要配置主机端口访问规则和 Windows 防火墙；日常聊天仅开放必要服务。S3 管理与查询控制权限另行明确。
- S3 保持本地 2.4 GHz Wi-Fi → Console 的 VVOS TCP `9000` 链路，由附近 PC 承接远程访问。首轮不需要让 S3 运行组网客户端或增加子网路由。
- 核查直连 / DERP 状态、异地登录/群聊/100 MiB 附件/掉线续传，记录目标网络和实测结果。Tailscale 组网加密覆盖参与组网的 PC；本地 S3↔Console TCP 段保持现有实现。
- 主机仍需开机、联网；核查托管服务地区可达性和企业计划。手机可作为 PC 的热点，移动 LanChat 客户端仍待开发。

### 第三步：外部大模型 API（后续评估）

目标是让板端及 LanChat 的交互获得自由对话和自然语言理解能力，模型推理在外部完成。

- 建议由 **PC / Console 管理 API 调用、凭据、费用和会话**，S3 提供状态并展示精简结果。若决定 S3 直接调用 API，再评估 TLS、超时、内存预算、凭据保护和网络条件。
- 模型通过明确的只读查询接口取得真实状态；解释必须依据快照及有效性，数据缺失时明确说明。
- 先确定模型提供方、密钥来源、费用限额、数据发送范围和会话保留方式，再接入。自由聊天与设备查询分别验证，后续控制命令需另定权限。
- 当前 `RoboMind-S3/main/chat_engine.cpp` 是历史外部 API 客户端，正常终端启动未启用；S3 没有运行聊天大模型。恢复历史代码不等于当前硬件与终端已完成接入验收。
