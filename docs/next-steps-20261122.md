# 实施进度与后续入口：Tailscale 与设备状态查询

决策日期：2026-11-21；实施更新：2026-11-23（Asia/Shanghai）。

四项只读查询已实现、部署并通过真实服务端 / Console / COM3 板端验收。Tailscale 本机安装与接入已完成；用户当前只有一台 PC，异地两机验收待第二台 PC。2026-11-23 新增 PC 外部模型接口和文字状态自由问答，见文末最新进度；语音与小智通用 AI 为后续。

## 1. 用户已确定的方向

1. 异地连接采用 **Tailscale 托管组网**，保留现有常开 LanChat 消息主机。ZeroTier 保留为备选资料。
2. 反馈交互先做 **感知、链路、设备、帮助** 四项只读查询，按明确的关键词和有限同义词识别。
3. 查询稳定后，再评估 **外部大模型 API**，让用户能够通过自然语言查询、解释设备状态和进行自由对话。
4. 专用 Unicode 表情选择面板继续保留待办；PC 附件继续与 S3 文字链路隔离。

## 2. 实施顺序与当前结果

### 第一步：四项只读查询（初版已完成）

沿用当前入口和协议职责：

```text
LanChat 私聊 / 配置群
    → Console 识别查询、保存发起者与会话
    → 感知 / 链路 / 设备经 VVOS 请求 S3 快照；帮助由 Console 回答
    → S3 返回结构化状态
    → Console 汇总并格式化
    → LanChat 回复原会话
```

| 查询 | 数据来源与结果 |
|---|---|
| 感知 | PPM 快照：疲劳、眼睛、嘴部、离开时长、退化标志、采样时间及逐项有效性 |
| 链路 | S3 Wi-Fi 与 VVOS 收发状态，加上 Console 的板端连接、LanChat 登录、最近通信时间 |
| 设备 | S3 运行时间、内部堆、最大连续块、PSRAM、模块接入情况 |
| 帮助 | 四项查询的输入方式与能力范围 |

实现约束：

- 私聊专用设备账号可输入 `感知` / `链路` / `设备` / `帮助`；配置群采用明确的 `/感知` 等命令。支持有限同义词和英文别名，完整匹配；正文中的任意子串不能触发。
- 回复关联原 LanChat 消息 ID，并回到发起查询的会话；请求 ID、超时和判重沿用有界处理方式，避免重连/重试产生重复回复和机器人自回复循环。
- 感知逐项保留 **未计算 / 无效 / 有效**，不能将缺失、无目标或无效结果写成“正常”。带采样时间、数据年龄，明确区分当前快照、历史缓存和离线。
- Console 负责综合链路回答。S3 断开后，在线的 Console 仍可返回“板端离线”；需要板端数据的查询返回不可用或明确标记的缓存。
- 状态读取不能阻塞 LVGL、摄像头或现有 TCP pump。S3 继续使用 VVOS 信封，LanChat JSON、账号和会话路由留在 Console。
- 内存、运行时间、Wi-Fi 和感知数据通过新增 `device/query` / `device/query_reply` 请求当前快照；旧固件能力不足时明确提示升级。
- 查询回复在 PC 聊天框完整展示；原查询文字继续进入板端收件箱，显示回执与查询回复分别记录。板端摘要仍受现有 384 字节 UTF-8 上限和字库覆盖约束。附件不进入查询或板端链路。

分工与验收：

- **LanChat-Next**：保持单次消息回显；如有需要增加设备查询帮助入口和会话展示，不再打开额外窗口。
- **RoboMind-Console**：查询路由、同义词表、状态汇总、按原私聊/群回复、限流、超时与判重。
- **RoboMind-S3**：结构化状态快照和 VVOS 请求/响应，保留现有显示、回执及感知数据流。
- 正向检查四项查询、中文、私聊和配置群；负向检查普通聊天不触发、附件不触发、机器人回复不循环、断线/无数据/无效数据有明确回答、重复请求只回一次。
- 涉及固件后执行协议测试、完整构建、烧录同一产物及真板查询往返验证；未完成实机验证不标记完成。

已完成的验收与资源：

- Qt 11/11、S3 协议 host test、Console 查询与原显示桥回归通过，覆盖私聊 / 群、限流 / 4 项并发上限、误触发、离线 / 旧固件 / 无效 / 过期 / 超时、重复请求 / 回复及附件过滤。
- 真实 LanChat 服务端 + Console + COM3 S3 使用临时账号和隔离数据库，四项私聊及一次群聊得到 **5 条回复并持久化，没有重复**；requested=5、replied=5、pending=0、invalid=0。测试未向正式账号或群发送消息。
- S3 完整构建、4 段烧录写入与哈希校验通过，最终固件启动后 25 秒无崩溃。TCP task 从 4096 扩为 **6144 字节**，实测查询栈余量 **2352 字节**；protocol/TCP 可写静态区仍为 24 字节。具体协议和边界见 [S3 查询协议](https://github.com/Nagi-226/RoboMind-S3/blob/master/docs/status-query-protocol.md)。
- 真板感知样本为“未计算”，此验收证明查询通信、路由和状态语义，不能作为感知算法准确度结论。

### 第二步：Tailscale（本机已完成，异地两机待验）

2026-11-22 已安装官方 Windows 客户端 1.104.7，确认 Running / 在线 / 无健康告警、UDP 可用，并放行虚拟 IPv4 上 TCP 12346 的窄范围防火墙规则。本机访问该虚拟地址成功；消息主机以独立后台进程运行，关闭聊天窗口不会停止它。实际地址仅记录在本机交接文档。

本机访问自身地址只证明本机接入和监听，不能证明异地直连 / 中继或跨网络传输。未修改 tailnet 全局访问策略，未自动创建开机任务。后续操作见 [Tailscale 接入说明](tailscale-setup.md)。

- 待第二台 PC 可用时，安装官方客户端并取得同一受控 tailnet 的访问权限；涉及第三方账号、计划选择和设备授权时由用户完成身份操作。
- 在 LanChat 填主机 Tailscale 地址或可解析的 MagicDNS 名称及 TCP `12346`。组网授权与 LanChat 注册/群 ID 是独立的访问层。
- 按实际需要配置主机端口访问规则和 Windows 防火墙；日常聊天仅开放必要服务。S3 管理与查询控制权限另行明确。
- S3 保持本地 2.4 GHz Wi-Fi → Console 的 VVOS TCP `9000` 链路，由附近 PC 承接远程访问。首轮不需要让 S3 运行组网客户端或增加子网路由。
- 核查直连 / DERP 状态、异地登录/群聊/100 MiB 附件/掉线续传，记录目标网络和实测结果。Tailscale 组网加密覆盖参与组网的 PC；本地 S3↔Console TCP 段保持现有实现。
- 主机仍需开机、联网；核查托管服务地区可达性和企业计划。手机可作为 PC 的热点，移动 LanChat 客户端仍待开发。

### 第三步：外部大模型 API（文字初版已实施，以下为原规划）

目标是让板端及 LanChat 的交互获得自由对话和自然语言理解能力，模型推理在外部完成。

- 建议由 **PC / Console 管理 API 调用、凭据、费用和会话**，S3 提供状态并展示精简结果。若决定 S3 直接调用 API，再评估 TLS、超时、内存预算、凭据保护和网络条件。
- 模型通过明确的只读查询接口取得真实状态；解释必须依据快照及有效性，数据缺失时明确说明。
- 先确定模型提供方、密钥来源、费用限额、数据发送范围和会话保留方式，再接入。自由聊天与设备查询分别验证，后续控制命令需另定权限。
- 当前 `RoboMind-S3/main/chat_engine.cpp` 是历史外部 API 客户端，正常终端启动未启用；S3 没有运行聊天大模型。恢复历史代码不等于当前硬件与终端已完成接入验收。

## 5. 2026-11-23：文字状态自由问答

用户决定先完成 LanChat 文字自然提问与状态追问，之后再做语音、小智通用 AI，并授权使用本机已配置的 DeepSeek Anthropic 兼容接口做少量联调。

Console 每轮获取三类经原查询校验的真实快照，调用 Anthropic / OpenAI 兼容接口，回复原私聊 / 配置群。私聊可直接自然提问，群用 `/AI 问题`；`/AI 清空` 清空模型上下文。状态无效、过期、离线、未计算和 ZAO_MINI 未接入如实提供；模型没有设备控制工具。

LanChat 本体增加接口配置、DPAPI 加密密钥和问答会话导航，当前主机已导入用户授权的本机配置并部署。模型上下文最多三轮，仅留内存；聊天记录继续由 LanChat 保存。每请求最多 1200 输出 token / 45 秒，失败不自动重试。发送范围为问题、状态摘要和最近几轮对话，图像、附件、完整日志和密钥不提供给模型。

两种接口模拟器、原查询回归、Qt 14/14 与问答配置 / 导航检查通过。真实 LanChat 服务端 + Console + COM3 S3 已得到三次模型回答，验证追问、群路由与单次持久化；使用临时账号和隔离数据库。模型回答准确度不作为感知算法验收。细节见 [问答说明](ai-status-chat.md)。
