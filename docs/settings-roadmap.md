# 设置使用说明与小智架构

更新：2026-11-23（Asia/Shanghai）。六组设置已在 Qt 客户端实施，入口为登录后的 **左下角齿轮 → 设置**。本机版本 2026.11.23.2；完整安装包的内容、校验和验收见[发布记录](windows-release-20261123.md)。

## 已实现设置

| 顺序 | 设置分组 | 必要选项与边界 |
|---|---|---|
| 1 | 账号与连接 | 当前账号 / 主机、退出登录、记住账号管理；连接检测、重连、LAN / Tailscale 指引。清除已记住的密码与删除聊天历史分别处理 |
| 2 | 通知与窗口 | 私聊 / 群 / 板端告警通知开关、提示音、免打扰、托盘与关闭行为、开机启动。消息主机托管状态要可见，防止关窗口后误以为主机仍运行 |
| 3 | 附件与存储 | 默认下载目录、缓存使用量与清理、自动下载限制；提示未完成的传输。共享主机附件额度只由主机管理者修改 |
| 4 | AI 与会话 | 接口检测、输出长度 / 超时、每天调用次数上限、使用统计、清空上下文。请求次数 / token 统计与提供方实际账单分开显示；确定性查询继续可用 |
| 5 | 显示与设备 | 字体大小 / 缩放、板端默认页面、重连偏好、日志级别 / 自动跟随 / 采集开关。USB 操作只作用于连接板子的主机 |
| 6 | 关于与诊断 | 客户端 / Console 版本、更新来源、复制脱敏连接诊断、导出必要日志；不导出密码或 API 密钥 |

设置页沿用深色侧栏与圆角表单；另有服务器 / 板端连接分类。首次安装保留登录页地址输入。设置保存后立即应用，AI 限额变更会重新启动本机桥；进行中的模型回答应先完成。

- **账号与连接**：查看账号 / 主机和托管状态；检测 TCP 连接、重连、清除记住的账号与密码、退出登录。清除记住信息不会删除服务器聊天历史。主机由独立进程托管时，退出此客户端不会停止它；客户端自行启动的主机在程序退出时停止，收起到托盘继续运行。
- **通知与窗口**：私聊 / 群 / 板端通知默认开启，提示音默认关闭；免打扰、关闭到托盘、登录 Windows 后启动。只通知实时新消息，服务端 echo、历史同步和正在查看的会话不重复提醒。开机启动只作用于当前 Windows 用户，不自动登录账号。
- **附件与存储**：默认下载目录为系统下载目录的 `LanChat/`，可调整 / 打开。完整下载经过 SHA-256 校验后同时保存至下载目录；已有不同内容的同名文件不会覆盖。自动下载只作用于新图片 / GIF，默认关闭，上限默认 10 MB；普通文件仍需点击下载。缓存默认 512 MB，按账号与主机隔离；清理只将完成缓存移入回收站，已保存下载、聊天历史、`.part` 与活跃传输保留。退出时有未完成任务会提示，下次可继续。
- **AI 与会话**：模型列表检测只发 GET，不生成回答、不发送问题或板端状态；部分渠道不提供 `/models`，不能据此判断文字接口失效。输出 token、超时、每日次数、全局间隔和并发可配置；默认 1200 token / 45 秒 / 每日 100 次 / 2 秒间隔 / 最多 4 个任务，每会话最多一个。次数先落盘再调用，失败占一次，重启保留、按主机本地日期跨日恢复；0 次上限表示不限。输入 / 输出 token 来自服务商响应，未返回 usage 时不估算。界面计数不是账户余额或账单。可提交本人板端私聊的 `/AI 清空`，聊天历史保留。
- **显示与设备**：字体 85–150%，即时应用并重算长气泡高度；默认板端页面可保持现状或五页任选，在支持页面控制的固件连接后应用一次。桥意外退出后可自动重连，主动断开不会自动启动；此选项不能解决 S3 的 Wi-Fi 配网。日志筛选 / 跟随偏好持久化，采集开关只作用于本机 USB 串口。
- **关于与诊断**：客户端版本、Console 上报版本、发布页、复制 / 导出白名单状态字段的 JSON。未包含密码、API 密钥、聊天正文、完整配置或原始报文。板端日志导出仍在板端连接的运行日志页使用，保留脱敏和筛选规则。

## HTTP 429 的历史记录（2026-11-23）

2026-11-23 21:30 的本机桥快照为 requested=1、failed=1、replied=0；聊天显示 HTTP 429，旧版未保存服务商的具体错误分类，因此不能断言是用户发得太快或余额不足。新版本根据服务商错误字段区分限流 / 余额或额度不足 / 原因不明确；不将原始错误正文或密钥送进聊天。按 `Retry-After` 的秒数 / HTTP 日期冷却，缺省 60 秒，范围 1–3600 秒，重启保留冷却状态，不自动重试。共享额度也可能被其他应用占用，请以服务商账户信息为准。

部署后最新生产状态捕获 `deepseek-flash` 的 HTTP 429，根据服务商错误字段归类为 `rate_limit`（限流），提示暂停 60 秒；复核时冷却已结束。此次限流的具体账户规则仍需由服务商平台确认，不能据此认定是本机提问过快。GET 模型列表检测成功并找到该模型，只证明列表可访问；当前没有新的成功生成记录，尚不能确认生成回答已恢复。安全摘要保存于本机 `build/settings-20261123/provider-latest-429.json`，本轮没有主动重发生产生成请求。

本机模拟回归验证三类 429、冷却 / 重启持久化、每日上限 / 跨日、token 计数、确定性查询和脱敏。界面新增选项通过 Qt 回归；Windows 开机启动与实际提示音仍需用户启用后确认。

## 小智是否是板子里的独立大模型

**不是。** 小智是开源设备固件和配套服务方案，提供语音交互、连接、屏幕和工具调用接口；自由对话能力通常来自服务端的大模型。

| 部分 | 一般职责 | 本项目当前状态 |
|---|---|---|
| ESP32-S3 | 麦克风 / 扬声器、离线唤醒、音频编码、联网、显示、设备工具 | RoboMind 五页终端、OV5640 感知与 VVOS 状态；未启用小智语音 |
| 小智配套服务 | 设备接入、ASR / TTS 或实时语音模型、会话与模型路由 | 待选型 / 接入；可使用托管服务或适配其他后端 |
| 对话大模型 | 理解问题、生成回答、按允许的接口使用工具 | 当前由 PC Console 调用配置的外部 API；不在 S3 运行 |

ESP-SR 离线唤醒可能使用板端小模型，它只识别唤醒词 / 有限语音指令，不能据此认为自由对话也离线运行。具体聊天模型取决于服务提供方和后端配置，不能仅凭“小智”名称确定是哪家模型。

上游 README 明确说明使用 Qwen / DeepSeek 等模型，提供 ESP-SR 离线唤醒、WebSocket 或 MQTT + UDP、Opus 音频与 ASR + LLM + TTS / 实时语音模型管线。参考：[xiaozhi-esp32](https://github.com/78/xiaozhi-esp32)、[WebSocket 协议](https://github.com/78/xiaozhi-esp32/blob/main/docs/websocket.md)。
